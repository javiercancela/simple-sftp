## What is not covered on this box

- **Packaged builds on macOS and Windows** (spec 11, 3.2 step 6): the `.dmg`
  (arm64, x64) and the Windows installer have never been built or run; the CI
  workflow that would build them on matching runners is untested.
- **Packaged UI exercise**: the E2E suite drives the production bundle with
  the development Electron binary (the release fuses block automation). The
  packaged artifacts themselves are covered by `smoke:packaged` (transport,
  download, normal UI start), not by the full UI suite.
- **Clean-machine install (A1)** and an `apt install` of the `.deb` (no root).
- **Linux baseline**: spec 11 names Ubuntu 24.04+; only Debian 13 was tested.
- **Windows**: no OpenSSH integration or E2E coverage (unit tests only).

## Other release checks done in step 5

- Fresh clone: `git clone` → `npm ci` → `npm start` opens the first-run
  screen (verified headless through a localhost DevTools port; screenshot
  `docs/screenshots/39-fresh-clone-npm-start.png`); README fixture steps
  (`scripts/fetch-test-sshd-debian.sh`, exports) → `npm test` passes in the
  clone. This found and fixed a bug: in `npm start` every IPC call was refused
  because the dev-server URL lacked a trailing slash in the sender check.
- Packaging: Electron's release zip carries world-writable modes, which made
  the installed executable `0777`; a Forge `postPackage` hook now clears
  group/other write bits and `smoke:packaged` checks the package, `.deb` and
  `.zip` listings.
- Licence notices: `THIRD_PARTY_NOTICES.md` (generated; shipped in
  `resources/`); a unit test fails when it is stale.
